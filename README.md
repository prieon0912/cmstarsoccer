# Floodlight Eleven

야간 경기장에서 즐기는 11대11 3D 축구 게임. 휴대폰 가로 모드에 맞춰 만들었습니다.

- 조작(FC Mobile 버튼 배치): 왼쪽 조이스틱으로 이동, 오른쪽 아래 큰 **질주** 버튼, 그 위 **슛**, 슛 왼쪽 **스루**, 질주 왼쪽 **패스**. 수비 때는 교체·압박·태클, 압박+질주를 같이 누르면 협력 수비.
- **패스**는 조이스틱이 가리키는 동료에게 가고, 누른 시간이 세기예요. 게이지의 흰 눈금이 알맞은 세기이고, 모자라면 느리게 굴러가 끊기기 쉽고 넘치면 받는 선수가 공을 흘려요(톡 치면 자동 세기). 패스를 누른 채 위로 밀었다 떼면 **롱패스**, 측면 깊은 곳과 코너킥에서는 **크로스**.
- **스루**는 달리는 동료와 공이 수비보다 먼저 만나는 지점을 계산해 찔러 주고, 누른 시간이 얼마나 앞으로 보낼지예요. 누른 채 위로 밀면 **로빙 스루**.
- **슛**은 길게 눌러 파워를 모으고, 떼기 전에 위로 밀면 칩슛, 아래로 감아차기, 오른쪽 파워 슛, 왼쪽 페이크 슛. 패스·스루·슛 게이지는 모두 같은 속도로 차요.
- **개인기**: 질주 버튼을 누른 채 위·아래·왼쪽·오른쪽으로 스와이프. 방향마다 넣을 기술은 전술 화면에서 13가지(라 크로케타 포함) 중 고릅니다. 선수마다 개인기 별(★1~5)이 있어 별이 모자라면 쉬운 기술이 나갑니다.
- **오프사이드**가 적용되고, 선수마다 숨은 성향(침투형·연결형, 공격/수비 가담, 압박 스타일 등)이 있어 움직임이 달라요. 전술 화면에서 선수를 누르면 성향 태그가 보여요.
- 경기 중 오른쪽 위 **AUTO**(키보드 T)를 누르면 컴퓨터가 대신 플레이하고, 다시 누르면 직접 조종으로 돌아옵니다(1인 경기만). 일시정지 메뉴에서 경기를 나가거나, 리그 경기는 기권(0:3 패배)할 수 있습니다.
- 키보드: WASD/방향키 이동, J 패스, U 롱패스·크로스, K 스루, I 로빙 스루, L/Space 슛, E 감아차기, R 칩슛, Shift 질주, 1~4 개인기, Q 협력 수비, C 카메라, P 일시정지.

## 프리미어리그 시즌

첫 화면이 리그 화면입니다. 처음 들어오면 시즌을 함께할 클럽을 고르고, 38라운드(홈·원정 각 19경기)를 치릅니다. 프리미어리그뿐 아니라 라리가·분데스리가·리그 1·세리에 A 구단도 선택할 수 있어요. 타 리그 구단은 PL 목록의 마지막 구단 자리를 대신해 20팀 리그에 참가해요. 계정이 있으면 **★ 내 팀으로 참가**를 끄고 구단을 고르면 해당 구단의 실제 선수단으로 플레이해요.

- **경기 시작**: 이번 라운드 내 경기를 직접 뜁니다. 끝나면 같은 라운드의 나머지 9경기는 클럽 전력(OVR)과 홈 이점으로 결과가 정해집니다.
- **결과만 보기**: 내 경기까지 포함해 라운드 전체를 시뮬레이션합니다.
- 순위표(챔피언스리그권·강등권 표시), 지난 라운드 결과·다음 일정, 득점 순위를 볼 수 있습니다.
- 시즌 기록과 클럽별 전술은 브라우저(localStorage)에 저장됩니다. **새 시즌**에서 클럽을 다시 고를 수 있습니다.
- **친선 경기**는 리그 기록과 상관없이 아무 두 팀이나 붙입니다.

선수 명단은 2026-27 시즌(2026년 10월 말) 기준이라 이후 이적·부상은 반영되지 않았을 수 있습니다. `public/index.html` 위쪽의 `CLUBS` 배열(클럽 이름·리그·유니폼 색·포메이션·선발 11명 [이름, 등번호, 역할, OVR]·교체 9명 [이름, 등번호, 포지션, OVR])을 고치면 바로 반영됩니다. 구단 엠블럼과 리그 로고는 넣지 않았고, 개인·비상업용으로만 쓰는 것을 전제로 합니다. 선수별 능력치(속도·슈팅·패스·드리블·수비·피지컬·개인기 별)는 바로 아래 `PSTAT_SRC` 표에 한 줄에 한 클럽씩 적혀 있어요. FC 시리즈 능력치 경향을 참고해 추정한 값이라 자유롭게 고쳐도 됩니다.

## 클럽과 선수 (2026-27)

- 프리미어리그 20개 클럽(2026-27 승격팀 코번트리·헐 시티·입스위치 포함)과 라리가(레알 마드리드·바르셀로나·아틀레티코·아틀레틱), 분데스리가(바이에른·도르트문트·레버쿠젠·라이프치히), 리그 1(PSG·마르세유·모나코·리옹), 세리에 A(인테르·밀란·유벤투스·나폴리) 16개 클럽, 총 36개 클럽이 있어요.
- 리그 모드는 기본 프리미어리그 20팀으로 돌아가며, 타 리그 구단을 선택하면 PL 한 자리를 대신해 참가해요. 36개 구단 모두 리그·친선 경기·1대1 온라인·계정 시작 클럽으로 고를 수 있어요.
- 클럽마다 선수 20명(선발 11 + 교체 9). 선발은 2026년 10월 말 실제 라인업 기준이고, 교체 명단은 EA SPORTS FC 27 공식 팀 명단으로 확인했어요.
- 능력치(OVR·속도·슈팅·패스·드리블·수비·피지컬)는 **EA SPORTS FC 27 출시 공식 능력치**(ea.com 팀별 레이팅)를 그대로 썼어요(720명 중 713명). 공식 값이 없는 7명(고레츠카, 체마 안드레스, 하잠, 그보호, 아펜그루버, 부아디, 맥에이두)만 추정치예요. 개인기 별은 드리블 수치로 계산해요. 등번호 일부는 추정이에요.
- 컴퓨터 팀은 58분·70분·80분 이후 멈춘 상황에서 지친 선수를 같은 포지션 교체 선수로 바꿔요.

## 최근 변경 (수비·키퍼·개인기·프리킥·리그·카드)

- **스탠딩 태클**: 태클은 수비수가 공 쪽으로 몸을 틀어 발을 뻗는 동작이고, 발끝이 실제로 공에 닿아야 성공해요(거리 1.5m에서 공을 빼앗는 '블루투스 태클' 없음). 볼 운반자 등 뒤에서는 AI가 스탠딩 태클을 걸지 않아요. 앞을 막고 선 수비는 더 적극적으로 태클해요.
- **골키퍼**: 손(다이빙한 몸 위치 + 팔 길이)이 실제로 닿는 곳에서만 선방이 돼요. 반응 범위와 선방 확률도 낮췄어요(같은 조건 슈팅 테스트 선방률 69% → 54%).
- **개인기**: 헛다리·힐 투 힐·라 크로케타 등은 속도를 유지한 채 하고, 끝나면 자연스럽게 가속해요. 동작 폭(골반·발·공 이동)도 커졌어요.
- **프리킥**: 슈팅 거리(골문 31m 안쪽, 중앙 쪽)면 슛 조준, 그 밖이면 일반 세트피스처럼 조이스틱 방향으로 패스. 슈팅 프리킥에서 패스는 좌우로 밀면 그쪽 동료, 그냥 누르면 가까운 빈 동료에게 가요.
- **리그를 내 팀으로**: 새 시즌을 시작할 때 "★ 내 팀으로 참가"를 켜고 클럽 자리를 고르면 내 팀이 그 클럽의 일정을 치러요.
- **선수 카드**: 팀 설정의 선수는 FC 모바일 같은 카드로 보여요. 베이스 카드는 실버 육각형이에요.

## 계정 · 내 팀 · 교체

- 메뉴의 **팀 설정**에서 계정을 만들 때 고른 **한 클럽의 선수 20명 베이스 카드**를 받아요. 주전 11명이 선발, 나머지 9명이 교체 명단으로 시작해요.
- 경기장 자리나 교체 자리를 누른 다음 다른 자리를 누르면 서로 바뀌고, 오른쪽 카드 목록(이름 검색·포지션 필터)을 누르면 그 선수가 들어가요. 교체 명단은 최대 9명.
- **단일팀 보너스**: 선발 11명이 모두 같은 클럽 카드면 모든 능력치 +3(OVR +3).
- 팀 이름·약칭·유니폼(어느 클럽 것이든)·포메이션·운영·**개인기 4방향 설정**도 팀 설정에서 바꿔요. 리그·친선 클럽용 전술 화면은 따로 남아 있어요.
- 계정은 브라우저(localStorage)에 저장돼요. 여러 계정을 만들 수 있고, **내보내기 코드**를 복사해 다른 기기에서 가져올 수 있어요.
- **친선 경기**에서 "★ 내 팀"을, **1대1 온라인**에서도 "★ 내 팀"을 고를 수 있어요(상대 브라우저로 팀 정보가 전달돼요). 리그 시즌은 **★ 내 팀으로 참가**를 켜면 내 팀으로, 끄면 선택한 실제 구단으로 치러요.
- 경기 중 일시정지 → **선수 교체**: 경기당 최대 5명, 체력 막대를 보고 바꿔요. 나간 선수는 다시 못 들어와요. 온라인에서는 게스트의 교체 요청을 호스트가 처리해 양쪽에 똑같이 반영돼요.

## 1대1 온라인

리그 화면의 **1대1 온라인**에서 내 팀을 고른 뒤 빠른 매칭 또는 4자리 방 코드로 상대와 11대11 경기를 합니다. 각자 자기 팀의 선택된 선수를 조종하고 나머지는 AI가 움직입니다.

- 방을 만든 쪽(호스트) 브라우저가 경기를 계산하고, 상대(게스트)는 조작을 보내고 호스트가 보낸 화면 상태를 그립니다. 서버는 둘을 짝지어 메시지를 중계만 합니다.
- 게스트 화면은 뒤집어서 보여 주므로 두 사람 모두 자기 팀이 오른쪽으로 공격합니다.
- 배포된 서버(Render)에서 열었을 때만 동작합니다. `file://`나 claude.ai 아티팩트에서는 1인 모드만 됩니다.

## 구조

- `public/index.html` — 게임 전체 (three.js r128을 cdnjs에서 불러옴)
- `server.js` — Express로 `public/`을 서빙하고 `/ws`에서 1대1 매칭·중계(WebSocket)
- `render.yaml` — Render 배포 설정 (Blueprint)

## 선수 모델과 동작

- `public/assets/player.json` — three.js 예제의 X Bot(Mixamo) 모델을 약 1만 폴리곤으로 줄인 GLB를 base64로 담은 것. 유니폼·피부·머리색은 게임의 셰이더가 칠합니다.
- `public/assets/clips.json` — three.js 예제의 Soldier(걷기·달리기·대기)와 Michelle(삼바, 골 세리머니) 모션캡처 동작을 X Bot 골격에 맞게 변환한 것.
- 킥·다이빙·태클·슬라이딩·스로인 등 축구 동작은 코드에서 만든 자세를 같은 골격에 섞어 씁니다.
- 원본 모델과 동작은 Mixamo에서 나온 것으로 three.js 저장소(examples/models/gltf)에 포함된 파일입니다.

## 로그인 계정과 DB

- 서버(`server.js`)가 게임 파일, 1대1 중계(WebSocket), 로그인 API(`/api/...`)를 같이 맡아요.
- 아이디·비밀번호로 회원가입/로그인하면 팀·개인기가 Postgres에 저장돼서 어느 기기에서든 같은 팀으로 플레이해요. 비밀번호는 scrypt 해시로만 저장되고, 로그인은 60일짜리 토큰으로 유지돼요. 로그인 시도는 IP당 10분에 20번으로 제한돼요.
- 회원가입은 시작 클럽으로 선택한 구단의 카드 20장으로 새로 시작해요. 기존 기기 계정이 자동으로 덮어쓰지 않아요.
- 로그인 없이 쓰는 "이 기기 계정"(브라우저 저장)도 그대로 쓸 수 있어요.
- DB 연결은 환경 변수 `DATABASE_URL` 하나예요. 테이블(users, sessions, profiles)은 서버가 처음 켜질 때 알아서 만들어요. 값이 없으면 계정을 메모리에만 두고, 서버가 재시작되면 사라져요.

| API | 설명 |
|---|---|
| `POST /api/auth/register` | `{username, password, profile?}` → `{token, user, profile}` |
| `POST /api/auth/login` | `{username, password}` → `{token, user, profile}` |
| `POST /api/auth/logout` | 토큰 폐기 |
| `GET /api/me` | 내 정보와 저장된 팀 |
| `PUT /api/profile` | `{profile}` 저장 (최대 16KB) |
| `POST /api/me/delete` | `{password}` 확인 후 계정 삭제 |

## 로컬 실행

```
npm install
DATABASE_URL=postgres://user:pass@localhost:5432/fl11 npm start   # http://localhost:3000
```

(`DATABASE_URL` 없이 `npm start`만 해도 돌아가요. 계정이 메모리에만 남을 뿐이에요.)

## 배포 (Render + Neon)

1. [Neon](https://neon.com)에서 무료 프로젝트를 만들고 **Connection string**(`postgresql://...?sslmode=require`)을 복사해요. Render 무료 Postgres는 30일 뒤 만료되니 Neon을 써요.
2. Render 대시보드 → **New → Blueprint** → 이 GitHub 저장소를 고르면 `render.yaml`대로 웹 서비스가 만들어져요. 이때 `DATABASE_URL`에 1번 값을 넣어요.
3. 이후 `main`에 푸시할 때마다 자동 배포돼요. `https://<서비스이름>.onrender.com/api/status`가 `"store":"postgres"`면 DB가 연결된 거예요.

Vercel이 아니라 Render를 쓰는 건 1대1 온라인이 WebSocket 서버를 계속 켜 둬야 해서예요(Vercel 함수는 WebSocket 서버를 못 띄워요). 무료 Render는 15분 동안 접속이 없으면 잠들고, 다시 깨는 데 1분쯤 걸려요.

## 주발·약발 / 게이지·조직 수비 패치

- 주발과 약발은 720명 모두 선수별 자료를 고정해서 사용합니다. 718명은 EA FC 27 기본 선수 데이터(2026-09-12 공개 스냅샷), 고레츠카·맥에이두는 별도 확인 자료를 사용했습니다. 출처와 EA 선수 ID는 `public/assets/foot-sources.json`에 있습니다. 주발은 선수 프로필 기준이고, 약발 1~5는 실제 경기의 공인 측정치가 아닌 FC 게임 평가입니다. 5는 양발로 표시합니다.
- 공이 몸 어느 쪽에 있는지에 따라 차는 발을 고릅니다. 공이 중앙이면 주발을 쓰고, 약발로 차면 패스·슈팅 오차가 늘고 슈팅 속도가 조금 줄어듭니다. 약발 5는 양발의 성능 차이가 없습니다. 헤딩·스로인은 약발 패널티가 없습니다. 왼발 킥 모션은 좌우를 반전하며 온라인·리플레이에도 반영합니다.
- 팀 설정에서 선수를 선택하거나 전술 화면에서 선수를 누르면 주발·약발을 볼 수 있습니다. 히든은 공격/수비 가담, 침투/연결 성향, 자유 이동, 압박 성향, 후반 집중력, 태클 판단의 7개입니다. 히든 수치는 포지션·능력치 기반의 게임 설정입니다.
- 슛·패스·스루·로빙 게이지 완충: 0.85초 → 0.60초(충전 속도 약 42% 증가).
- 수비는 팀 전체가 공 위치를 공유하며 압박 1명·후방 커버 1명·나머지 지역 방어/상대 분담으로 움직입니다. 압박 담당을 잠시 유지해 잦은 교대를 줄이고, 같은 상대에게 마커가 겹치지 않게 분담합니다. 센터백과 풀백의 마킹 이동 범위도 제한해 라인이 무너지는 것을 줄입니다. 협력 수비 버튼은 추가 압박 요청으로 유지합니다.

## 크로스·라 크로케타·수신·종료 동작

- 화면에 크로스/롱패스 버튼(U)을 추가했습니다. 공격 진영 측면에서는 크로스, 나머지는 롱패스로 동작합니다. 기존 패스 위로 스와이프도 유지합니다. 충전량에 따라 가까운 포스트·페널티 지점·먼 포스트를 겨냥합니다.
- 라 크로케타는 전진을 잠깐 줄인 뒤 양발 사이로 공을 약 1m 옮기며 몸도 측면으로 약 1.5m 이상 빠지고, 반대발로 받아 재가속합니다. 1초 재사용 제한이 있으며, 개인기 설정에서 라 크로케타를 스와이프에 배정하면 사용할 수 있습니다.
- 공격 시 스트라이커·공격형 미드필더·반대편 윙어가 서로 다른 공간을 점유하도록 수정했습니다. 동료의 이동 예정 지점도 혼잡도에 반영하고, AI끼리 가까워지기 전에 서로 피하도록 했습니다. 패스를 받을 선수와 루즈볼 추격 선수가 중복되지 않도록 했습니다.
- 패스 수신 보조는 조이스틱 방향이 바뀌어도 공을 받을 때까지 유지합니다(패스 종료·소유권 변경·3.5초 경과 시 해제). 선택된 선수가 근처 루즈볼에 가장 가깝다면 조이스틱을 누른 상태에서도 공에 접근합니다. 공을 잡으면 곧바로 수동 조작이 돌아옵니다.
- 전·후반 종료 결과 화면에서는 잔여 이동·회전·액션을 초기화합니다. 골 세리머니도 움직이는 득점자를 따라 도는 대신 간격을 둔 고정 위치로 이동하도록 바꿨습니다.

검증: `npm test` 또는 `node --test tests/gameplay.test.cjs tests/accounts-league.test.cjs`.

## 브라우저 간 계정 동기화 (Neon 유지)

- 온라인 계정의 선수단(선발/벤치), 팀 이름·약칭·유니폼·포메이션·운영, 개인기 4방향과 구단별 전술을 서버 프로필에 저장합니다. 다른 브라우저에서 같은 아이디로 로그인하면 서버의 설정을 사용합니다. 비로그인 기기 계정은 브라우저에만 저장됩니다.
- 변경은 자동 저장하고, 로그아웃 전에는 저장 완료를 기다립니다. 창을 닫거나 다른 앱으로 이동할 때도 저장을 시도하며, 미전송 변경을 브라우저에 보관해 재접속 때 재시도합니다. 저장 전 강제 종료·통신 두절 시에는 재접속 후 전송이 필요할 수 있습니다.
- 로그인·창 복귀·메뉴 복귀와 메뉴에 머무는 동안 15초 간격으로 최신 프로필을 확인합니다. 경기 중에는 원격 설정으로 현재 팀을 교체하지 않습니다.
- 저장 버전이 다른 오래된 브라우저의 덮어쓰기를 차단합니다. 충돌하면 서버의 최신 설정을 불러오고, 미저장 변경은 기기 계정 목록의 **복구용** 계정으로 남깁니다. 응답만 유실된 동일 저장은 중복 변경 없이 복구합니다.
- 기존 `profiles` 테이블에 `revision` 열만 자동 추가합니다. 기존 선수단과 설정을 삭제하거나 Neon 프로젝트를 바꾸지 않습니다. 이전 클라이언트는 새로고침해야 저장할 수 있습니다.

### 기존 Neon 연결 확인

1. Render의 **cmstarsoccer → Environment**에서 `DATABASE_URL`이 기존 Neon 프로젝트의 연결 주소로 설정되어 있는지 확인합니다. 다른 이름으로 저장했거나 환경 변수 그룹이 연결되지 않았다면 서버가 읽지 못합니다. 비밀번호가 포함된 주소를 게임 파일·Git 저장소·채팅에 넣지 않습니다.
2. 코드를 배포하고 Render 서비스를 다시 시작합니다. 서버가 DB 연결 및 기존 테이블 마이그레이션을 마쳐야 정상 기동합니다.
3. `https://cmstarsoccer.onrender.com/api/status`에서 `store: "postgres"`, `persistent: true`, `profileSync: 2`인지 확인합니다. `store: "memory"`라면 브라우저끼리 접속 중에는 공유되더라도 서버 재시작 후에는 유지되지 않습니다.
4. 브라우저 A에서 팀·선수단·개인기를 변경하고 **저장됨**을 확인한 뒤, 다른 브라우저 B에서 같은 계정으로 로그인해 확인합니다.

메모리 모드에서만 저장된 계정은 Neon에 자동으로 존재하지 않습니다. 이미 Neon에 저장된 계정은 기존 연결을 복구하면 그대로 불러옵니다.

검증에는 실제 Neon이 아닌 별도의 임시 PostgreSQL 엔진과 로컬 로그인 API를 사용합니다. `npm ci` 후 `npm test`로 실행합니다.

## 관리자 로그인

- 게임의 기존 로그인 창에 관리자 아이디 `prieon_auth`와 지정한 관리자 비밀번호를 입력하면 **별도의 관리자 창**이 열립니다. 일반 게임 계정으로 로그인하는 흐름과는 분리됩니다. 브라우저가 팝업을 차단한 경우 현재 창에서 관리자 화면을 엽니다. `/admin/`으로 직접 접속해 로그인할 수도 있습니다.
- 최초 서버 시작 시 서버 전용 `lib/admin-bootstrap.json`의 아이디·scrypt 해시로 관리자 계정을 자동 준비합니다. 비밀번호 원문은 소스·브라우저 코드에 저장하지 않습니다. 같은 이름의 관리자가 이미 있으면 기존 비밀번호를 변경하지 않습니다. 배포 후에는 Neon 콘솔에서 수동으로 계정을 생성할 필요가 없습니다.
- 기존 Neon 연결을 유지합니다. DB에는 일반 계정과 분리된 `admins`, `admin_sessions` 테이블을 추가합니다. 일반 회원가입이나 게임 세션으로는 관리자 권한을 얻을 수 없습니다. DB 미연결 개발 모드에서는 임시 관리자만 준비되며, 실제 운영에는 기존 Neon의 `DATABASE_URL`이 필요합니다.
- 관리자 세션은 4시간 동안 유효한 별도 HttpOnly 쿠키를 사용합니다. 외부 사이트에서의 로그인 요청을 차단하고, 변경 요청에는 CSRF 검사를 적용합니다. 대시보드에서 저장 연결 상태, 패키지·확률, 선수 카드·히든, 클래스 디자인을 관리합니다.
- 관리자 비밀번호를 브라우저 파일이나 게임 로그인 코드에서 문자열 비교하는 방식은 사용하지 않습니다. 관리자 인증과 모든 관리자 API 접근은 서버가 확인합니다.
- 추가 관리자는 서버에서 `ADMIN_PASSWORD` 환경 변수를 설정한 후 `npm run admin:create -- <아이디>`로 만들 수 있습니다. 기본 관리자의 비밀번호를 바꾸는 도구는 아닙니다.

## 로그인·상점·카드 관리

- 메인 메뉴의 **로그인 / 회원가입**, **상점**, **팀 관리**가 각각 분리됩니다. 시작 구단은 회원가입 화면에서만 고릅니다. 로그인 상태에서는 메인 계정 버튼이 로그아웃으로 바뀝니다. 시즌을 시작하기 전에도 로그인과 상점을 이용할 수 있습니다.
- 온라인 계정은 최초 1회 1,000코인과 선택 구단의 베이스 카드 20장을 받습니다. 기존 온라인 계정도 지갑을 처음 만들 때 한 번 지급됩니다. 다른 브라우저 로그인·서버 재시작으로 중복 지급되지 않습니다. 비로그인 기기 계정에는 상점 재화가 지급되지 않습니다. 
- 자동으로 생성하는 기본 팩은 없습니다. 관리자가 등록하고 판매를 켠 패키지만 상점에 표시합니다. 이전 버전이 만든 기본 실버 팩(`base-silver`)은 다음 서버 시작 때 제거합니다. 상점에서 한 번에 1~10회를 선택하고, OVR별·선수별 최종 확률을 검색할 수 있습니다.
- 패키지별 이용 시작·종료 시각을 설정할 수 있습니다. 날짜를 비우면 해당 시작/종료 제한을 두지 않습니다. 관리자와 상점은 기기 시간으로 표시하고, 저장과 이용 가능 여부 판단은 서버 시각을 사용합니다. 시작 시각은 포함하고 종료 시각은 제외합니다. 시작 전·종료 후에도 확률은 볼 수 있지만 뽑기는 차단합니다.
- 결과는 실버 카드와 전광판 배경으로 보여 주며, 획득한 카드는 팀 변경 목록에 추가됩니다. 중복은 보유 수량으로 쌓입니다. 같은 실선수의 베이스·다른 클래스 카드를 동시에 선발/벤치에 배치할 수 없습니다.
- 코인·보유 카드는 서버에서 관리합니다. 뽑기 요청 번호를 기록하여 응답 유실이나 중복 클릭으로 재차 과금하지 않습니다. 결제와 카드 지급은 한 DB 트랜잭션으로 처리합니다. 가격·확률이 바뀐 상품은 새 정보를 확인한 뒤 다시 추첨합니다.

### 관리자 사용법

1. **패키지·확률 관리 → 새 패키지**에서 이름, 코인 가격, 판매 여부, 포함할 클래스, **이용 시작·이용 종료**를 설정합니다. 종료는 시작보다 늦어야 합니다. OVR별 비중을 입력하면 합계 100%로 환산한 확률을 보여 줍니다. `0`은 해당 OVR 제외입니다. 선수 균등/OVR 균등 설정 버튼도 있습니다.
2. **선수 카드별 특별 배율**에서 선수를 검색해 배율을 적용합니다. 기본은 1배, 0배는 제외입니다. 먼저 OVR을 추첨하고, 같은 OVR 안에서 배율로 선수를 추첨하므로 OVR 전체 확률은 유지됩니다. **실제 확률 미리보기**에서 상점과 동일한 계산 결과를 확인한 뒤 저장합니다. 대상 선수가 없는 OVR에 양수 비중을 설정하면 저장을 거부합니다.
3. **선수 카드·히든 관리**에서 이름·구단 ID·카드 ID를 검색하거나 클래스·OVR로 필터링합니다. 각 카드에 공격/수비 가담, 침투/연결 성향, 자유 이동, 압박 성향, 후반 집중력, 태클 판단 히든을 표시합니다. **히든 확인 / 편집**으로 6개 능력치, 7개 히든, 주발·약발, 개인기를 확인·수정합니다.
4. **새 카드**로 선수를 직접 추가하거나 기존 선수를 **새 카드로 복제**한 뒤 클래스를 선택합니다. 복제 시 실선수 식별자를 유지해 클래스가 달라도 동시 편성을 막습니다. 새 선수는 별도 식별자가 자동 생성됩니다.
5. **클래스 디자인**에서 클래스 ID·이름·색상·형태와 카드/뽑기 연출 배경/팀 배치 프레임을 설정합니다. 발롱도르(`BALLON_DOR`)와 ICON(`ICON`)은 기본 등록되고, 디자인 4종 프리셋을 고르면 이미지 경로·글자 색상·선수 등장 모션이 자동 입력됩니다. 베이스 실버 디자인은 고정입니다. 사용자 이미지는 `public/assets/`에 추가한 뒤 `/assets/...` 경로를 입력합니다.

### 발롱도르 · ICON 디자인과 선수 일괄 추가

- 발롱도르: 골드 시상식 / 미드나이트. ICON: 아이보리 신전 / 옵시디언. 카드·팀 배치 프레임과 패키지 개방·터널·선수 등장 모션을 포함합니다. `/class-designs.html`에서 4종을 재생할 수 있습니다.
- **선수 카드·히든 관리 → 클래스별 선수 추가** 또는 클래스 디자인의 **선수 추가**는 원본 카드 없이 신규 카드를 직접 등록합니다. 이름·구단·OVR·6개 능력치·7개 히든·주발·약발·개인기를 입력하고 저장합니다. 발롱도르 추천 설정 17종을 불러와 수정할 수 있으며, 저장하고 다음 선수 추가로 같은 클래스에 연속 등록할 수 있습니다. 추천 설정은 실제 목록에 자동 등록되지 않습니다.
- 패키지 편집의 **클래스별 뽑기 선수 추가**에서 **이 클래스만 사용** 또는 **기존 목록에 추가**를 누르면 해당 클래스의 선수들을 포함하고 선수 균등 확률로 갱신합니다. 이후 OVR별 비중·특별 배율을 설정하고 실제 확률을 미리 볼 수 있습니다.
- 새 클래스는 디자인만 등록되며 선수는 관리자가 골라 추가합니다. 기본 클래스 등록은 기존 관리자 디자인을 덮어쓰지 않습니다.
- 실제 뽑기는 최고 OVR 카드의 클래스 연출을 재생한 뒤 결과 목록으로 이어집니다. 건너뛰기·키보드 종료·동작 줄이기를 지원합니다. 디자인 미리보기는 결과 보기 버튼으로 닫습니다.

기존 Neon의 `DATABASE_URL`을 그대로 사용합니다. 서버 시작 시 `game_cards`, `card_classes`, `shop_packages`, `wallets`, `card_inventory`, `pack_draws`, `admin_changes`, `league_seasons` 테이블을 추가하고 최초 카탈로그만 채웁니다. 관리자 변경 사항을 재시작 때 기본값으로 덮어쓰지 않습니다. Render 배포 후 `/api/status`가 `store: "postgres"`인지 확인해야 관리자 설정·재화·보유 카드가 영구 보관됩니다.

검증: `npm test`. 임시 PostgreSQL 엔진으로 지갑·카드·카탈로그 재시작 복원, 지급 1회 제한, 동시 뽑기 중복 처리와 실패 시 롤백을 확인하며, 실제 Neon 데이터는 테스트에 사용하지 않습니다.

- 선수 공개 연출은 약 9.5초이며, 발롱도르는 황금공 트로피 장면 뒤 6초부터, ICON도 6초부터 실제 카드가 나타납니다. 건너뛰기와 동작 줄이기는 유지합니다.

- ICON 전당은 바닥 각인 → 월계관 문장 형성 → 빛 파편 응집 → 문장 해방과 파동 → 포지션·구단 → 6초 카드 공개의 별도 동작으로 구성합니다.

### 클래스별 패키지 확률

패키지는 클래스 확률 → 해당 클래스 내부 OVR 확률 → 같은 클래스·OVR의 선수별 배율 순서로 추첨합니다. 각 단계의 비중은 따로 합계 100%로 환산하며, 0은 제외합니다. 관리자 미리보기와 상점 확률 확인에는 클래스·클래스 내부 OVR·최종 선수 확률을 표시합니다. 기존 패키지는 저장 전까지 기존 방식으로 작동하며, 관리자 편집에서 새로운 구조로 변환할 때 최종 선수 확률을 유지합니다.

- 상점은 전체 공개 패키지 목록과 선택한 패키지 상세·구매 영역을 분리합니다. 1~10회 슬라이더로 횟수와 총 코인을 조절하며 패키지를 오가도 선택 횟수를 유지합니다. 확률 확인에는 검색 가능한 선수별 최종 확률표만 표시합니다. 패키지가 비공개면 상점에 나오지 않으며 관리자 저장 안내에 공개 상태를 표시합니다.

### 경기 흐름·조작 개선

- 로그인 계정의 시즌 진행도·대진·결과·득점 기록·직접 플레이 횟수·보상 상태를 선수단과 함께 기존 PostgreSQL 프로필에 저장합니다. 다른 기기 로그인·새로고침 시 복원하며 프로필 버전 충돌을 검사합니다. 기존 기기에 남은 동일 계정 소유의 시즌은 클라우드 시즌이 없을 때 자동 이전합니다. 예전 앱의 선수단 전용 저장은 기존 시즌을 삭제하지 않습니다. 다른 기기에서 진행 중인 경기의 표시는 자동 몰수패 복구 대상에서 제외합니다. 서버 재배포 후 기존 시즌이 남아 있는 기기에서 같은 계정으로 접속해야 이전 시즌을 올릴 수 있습니다.

- 화면 시계는 전반 45:00·후반 90:00에서 멈추지만 내부 시간은 계속 진행해 추가시간 종료를 판단합니다.
- 전후반 종료 시 진행 중인 공격은 유지합니다. 상대의 확실한 소유, 상대에게 주어지는 재개, 골로 공격이 끝나면 종료하고, 게임 시계 50분·95분에는 강제로 종료합니다. 득점 연출은 마무리합니다.
- 경기장은 105×68m로 조정하고 선수 충돌 간격과 문전 지원 위치를 정리했습니다. 포지션별 이동 구역·전진 상한·3선 경계·마크 이동 반경·추가 침투 상한을 제거했습니다. 포메이션과 공통 수비 라인은 기본 위치의 참고값으로만 사용하고, 가까운 조작 선수가 있어도 AI 압박을 유지합니다. 기본 수비 라인은 페널티 박스 앞 부근이며, 유효한 침투와 이미 출발한 패스의 수신자에 맞춰 내려갑니다. 이미 오프사이드인 공격수만 보고 라인을 내리지는 않습니다.
- AI가 기본 위치를 잡는 3선(CDM·CM·LM·RM)은 공격 방향으로 약 2.5m 전진하도록 조정했습니다. 기존 이동 자유도·마크·침투와 실제 오프사이드 판정을 유지하며, 직접 조작·볼 소유·진행 중인 침투·세트피스에는 추가 전진을 적용하지 않습니다.
- 박스 위험 상황은 가까운 수비수 한 명이 직접 압박하고, 두 번째 수비수는 약 2.8m 뒤·옆에서 커버합니다. 조작 선수가 가까이 있어도 AI 압박을 끄지 않습니다. 커버 목표는 골라인 밖으로 나가지 않습니다.
- 키퍼의 슛 반응·준비 자세 전환·다이빙 도달 속도·포구를 강화했습니다. 골문 앞 자동 대기와 실제 접촉 조건은 유지하며, 이동 중에도 공을 향해 몸을 정렬합니다.
- 일반 드리블의 전방 볼 간격, 필드 선수의 공 획득 범위와 태클 접촉 여유를 소폭 줄였습니다. 치고 달리기는 공을 먼저 밀어 보내는 별도 동작을 유지합니다.
- 키퍼 선방·공 수집은 현재 애니메이션 모델의 손·몸·다리와 공의 3차원 접촉을 확인합니다. 예측 시간에 맞춘 강제 선방과 넓은 사각형 판정은 제거했습니다. 빠른 슛은 물리 갱신 구간마다 이동 경로를 검사하며, 골라인을 이미 넘은 공은 선방으로 되돌리지 않습니다. 포구는 실제 손 접촉일 때만 가능합니다.
- 키퍼는 기본적으로 골라인 약 1.1m 앞에서 대기합니다. 중앙 일대일은 상대가 골문에서 23m 이내·중앙 좌우 14m 이내·키퍼에서 22m 이내이며 골문 사이에 수비 커버가 없을 때, 0.12초 확인 후 전진합니다. 상대 앞쪽 깊이가 1.5m 이하여도 무리하게 나가지 않습니다. 소유 상대를 압박할 때 최대 전진 목표는 골라인에서 9m입니다. 스루패스·느슨한 공은 슛이 아니고 박스 안(깊이 16.5m·좌우 14m 이내)에서 키퍼가 상대보다 0.15초 이상 먼저 닿을 수 있을 때 최대 11m까지 수집하러 나갑니다. 커버 회복·측면 이동·소유 변경 시 골문으로 복귀합니다. 직접 조작과 배급·경기 재개는 유지합니다.
- 선수 능력치와 공 속도는 유지하고 실제 이동 속도를 공통 0.9배로 조정했습니다. 일반 달리기·드리블·개인기·태클·골키퍼 이동과 교체 선수에 적용합니다. 일반 이동 방향과 몸 방향을 맞추고 드리블·속력에서 계산한 민첩성으로 회전·가감속을 조절합니다. 커서 드리블의 급격한 전환과 개인기는 공격자의 드리블, 상대 수비와 민첩성에 따라 반응 지연과 회복이 달라집니다.
- 흘러나온 공은 수집 범위까지 달려가며, 치고 달리기는 앞발에서 공을 밀고 쫓습니다. 라 크로케타 이동·볼 이동·효과 범위는 10% 줄였습니다.
- 스탠딩 태클의 일반 시도 빈도와 정확한 발 접촉 성공률을 강화하고 슛 준비와 경합 승리 직후 0.55초의 즉시 재탈취를 완화했습니다. 무적 시간은 아닙니다.
- 패스가 오는 동안 패스·스루·로빙·슛을 충전할 수 있습니다. 먼저 놓은 입력은 해당 패스가 도착할 때까지 유지하며, 끊긴 패스나 다른 수신자에게 적용하지 않습니다. 낮은 공은 첫 접촉에 바로 차고, 높은 공은 예약한 헤딩 슛·패스로 이어집니다. 누르고 있는 입력은 접촉 시점의 게이지를 사용합니다.
- 스루패스는 충전할수록 구속도 올라가며 수신 위치 계산에도 그 속도를 반영합니다. 파워슛은 강한 구속을 유지하되 준비 동작, 이동·거리 오차와 과충전 시 높은 슛 위험을 늘렸습니다.
- 리그 중퇴·경기 재시작·미완료 경기 새로고침은 0:3 몰수패로 한 번만 기록합니다. 친선·온라인 경기에는 이 처리를 적용하지 않습니다.
